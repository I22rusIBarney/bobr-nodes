# 🦫 Bobr Nodes

Telegram-бот с веб-админкой для админов: выбираешь панель, локацию и тариф — бот покупает серверы в **bcloud**,
ставит на них [Nuvrion Vision](https://github.com/nuvrion-kvn/Nuvrion-Vision-Installer) и регистрирует ноды в **Remnawave**.

## Установка

```bash
git clone https://github.com/I22rusIBarney/bobr-nodes.git
cd bobr-nodes
sudo ./install.sh
```

Установщик сам поставит Docker и спросит только:

1. **Токен нового бота** (от @BotFather) и **ваш Telegram ID**.
2. **Домен панели управления** — отдельный поддомен с A-записью на IP сервера, например `nodes.example.com`.

Если на сервере уже работает **bcloud**, установщик предложит подключиться к нему: сам включит служебный API bcloud,
возьмёт токен, выберет аккаунт для покупок и поставит панель за HTTPS bcloud (`bcloud site add`), так что порты 80/443
делить не придётся. Нужна версия bcloud с командами `bcloud api-token` и `bcloud site` (`bcloud update`).
На отдельном сервере бот поднимет свой Caddy с Let's Encrypt.

Дальше всё в **веб-админке**: откройте бота → «Панель».

- **Подключения** — bcloud (если не подключился сам), токен Cloudflare (*Zone → DNS → Edit*, *Zone → Zone → Read*),
  свой SSH-ключ для новых серверов, сколько нод ставить одновременно.
- **Профили панелей** — адрес Remnawave, API-токен, cookie-защита (вставьте секретную ссылку входа целиком), исходящие IP панели,
  email для Let's Encrypt, домен и шаблон автоимён, сквады. Панелей может быть несколько.
- **Развернуть** — панель → локация → тариф → срок → количество → домены (автоматически или вручную) → «Купить и установить».
  В «Порядке хостов» виден текущий список хостов панели: новые по умолчанию идут в конец, их можно поднять стрелками
  или поставить сразу после нужного хоста — бот переставит их, когда создаст.
  «Дополнительно на ноде → Psiphon» ставит вместе с нодой [vps-psiphon](https://github.com/Chara-Freedom/vps-psiphon)
  (закреплённый коммит, SOCKS5 только для самого сервера, без HTTP-прокси) и пускает выбранные домены — по умолчанию Google —
  через него. Рядом — **WARP** ([vps-warp](https://github.com/Chara-Freedom/vps-warp), выход `warp-out` с меткой 255,
  по умолчанию для `geosite:tiktok`). Ноды с дополнениями попадают в общий профиль `NV Vision Psiphon`, `NV Vision WARP`
  или `NV Vision Psiphon WARP` с нужными выходами и правилами в конце маршрутизации.
  «Подключение клиентов» — **порт** (443 или свой: на ноде он переадресуется на порт Xray, 443 тоже работает, фаервол
  открывать не нужно) и **Final Mask** хостов (по умолчанию фрагментация TLS ClientHello — против операторов, которые его режут).
- **Ноды в панели** (страница группы) — все ноды панели с профилем и дополнениями. Для любой из них: поставить Psiphon
  и WARP по SSH (нода переходит в копию своего профиля с этими выходами, её хосты и сквады — вместе с ней, остальные ноды
  не меняются), сменить порт и включить или убрать Final Mask на её хостах. Доступ по SSH: у нод, купленных ботом, он
  уже есть; для остальных — пароль или ключ бота (бот показывает его, на новые ноды кладёт сам).
- **Задачи** — этапы каждой ноды, журнал установки, «Повторить» для упавших.

- **Мои скрипты** — свои скрипты установки нод с GitHub. Даёте ссылку → бот закрепляет коммит и SHA-256 →
  Gemini разбирает скрипт: что делает, рекомендации, риски, вопросы — и предлагает рецепт (как запустить, что
  ответить, когда считать установку законченной, какие команды выполнить после, откуда взять профиль Xray).
  Можно переписываться с Gemini и править рецепт вручную; после «Утвердить» скрипт выбирается в группе.
  Ставит бот сам, строго по рецепту, без нейросети: на любой вопрос скрипта не из рецепта — остановка.
  Ключ Gemini — в «Подключениях» (если сервер в стране, где Gemini недоступен, — укажите прокси).

В чате с ботом — быстрый запуск того же мастера и сообщения о ходе каждой установки.

```bash
bnodes update    # обновить из GitHub
bnodes logs      # логи
bnodes backup    # копия базы и настроек
bnodes setup     # заново ответить на вопросы установщика
bnodes help
```

## Безопасность

В базе бота — root-пароли нод, токены панелей, Cloudflare и bcloud: доступ к серверу бота = доступ ко всем нодам.

```bash
bnodes harden     # файрвол UFW, fail2ban, усиленный SSH, автообновления, sysctl, сообщения о входах в бота
bnodes security   # что включено, сколько заблокировано, разрешён ли вход по паролю
```

Установщик предлагает `harden` в конце установки. Если на сервере уже есть защита bcloud, настройки дополняют её,
а не перетирают: оба бота получают сообщения о входах по SSH и подборе паролей. Главное — вход только по ключу:
`harden` предложит отключить пароль, если у root есть SSH-ключ.

Сам бот:
- веб-админка открывается только из Telegram (подпись initData, только `ADMIN_IDS`); после 20 запросов без доступа
  за 10 минут IP получает паузу; заголовки CSP, `nosniff`, `frame-ancestors` только Telegram;
- порт бота наружу не опубликован — только через HTTPS Caddy; контейнер без привилегий (`cap_drop: ALL`,
  `no-new-privileges`), логи с ротацией; CI проверяет образ в этих ограничениях перед публикацией;
- SSH к нодам: ключ сервера запоминается при первом входе (`data/ssh/known_hosts`); если он сменился — бот
  останавливается и пароль не отправляет. После переустановки системы — «Забыть ключ SSH» на странице ноды;
- `.env`, `data/` и копии `bnodes backup` доступны только root.

## Что происходит с каждой нодой

1. **Покупка в bcloud** с баланса выбранного аккаунта, со сгенерированным root-паролем.
2. **Ожидание IP**, сервер в bcloud переименовывается в имя ноды.
3. **Cloudflare**: A-запись домена → IP (серое облако), ожидание, пока DNS её отдаёт.
4. **SSH** под root, по желанию — добавление вашего ключа.
5. **Установка**: оригинальный установщик с закреплённого коммита, сверка SHA-256, ответы на вопросы автоматически.
   Незнакомый вопрос — остановка с его текстом, а не ответ наугад.
6. **Дополнения** (если выбраны): vps-psiphon и vps-warp со сверкой SHA-256, переадресация нестандартного порта.
7. **Панель** (через cookie-защиту): общий для всех нод профиль `NV Vision`, нода, хост (TLS, SNI, firefox, h2/http1.1), сквады,
   по выбору — балансировщик. Профиль один: на каждой ноде бот делает ссылку `/etc/letsencrypt/nv-node` → `live/<домен ноды>`,
   поэтому путь к сертификату у всех одинаковый, а тег inbound `Vision-NV` не конфликтует с нодами, поставленными вручную (`Vision-TLS`).
8. **Проверка** `installer.sh --check` на ноде.

«Повторить» не покупает сервер второй раз, если он уже куплен. После перезапуска бота незавершённые задачи продолжаются;
если бот упал ровно во время покупки, задача останавливается с просьбой проверить bcloud — вслепую второй сервер не покупается.

Автоимена: шаблон `{cc}{n}` → `de1.example.com`, `de2.example.com`…; занятые (в задачах или уже с DNS-записью) пропускаются,
«vpn» в шаблоне и домене запрещено.

Всё хранится в `data/bot.db` (токены — в открытом виде, папка доступна только root), журналы — в `data/logs/`.
Веб-админка открывается только из Telegram: подпись initData проверяется токеном бота, доступ — только `ADMIN_IDS`.

## Тесты

```bash
pip install -r requirements.txt -r requirements-dev.txt
pytest                                                                 # юнит-тесты
BCLOUD_DIR=../bobr-cloud NV_SRC=../Nuvrion-Vision-Installer/src pytest  # + сквозной сценарий
```

Сквозной сценарий поднимает настоящий bcloud с тестовой Astra, тестовые Cloudflare и панель, веб-админку и чат-бота
(Telegram подменён), а вместо SSH — имитацию установщика с его настоящими вопросами.
